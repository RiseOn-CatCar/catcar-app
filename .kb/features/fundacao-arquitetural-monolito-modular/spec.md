# Fundacao Arquitetural: Monolito Modular

## Context

This feature bootstraps the entire CatCar solution from an empty repository. It establishes the modular monolith structure — four Bounded Contexts, SharedKernel, Contracts, API composition root, Aspire AppHost, test infrastructure, Docker setup, and CI pipeline. Every subsequent feature (02 through 08) builds on this foundation. The strategic design decisions are archived at `[[design-estrategico-fases-1-2]]`; the tactical blueprint is at `[[fundacao-arquitetural-monolito-modular/design.md]]`.

## Acceptance Criteria

### Solution structure and compilation

- **AC-001** (ubiquitous): The system shall compile successfully with `dotnet build` on the entire solution, targeting .NET 10.0 (net10.0) with C# 14, Nullable enabled, and ImplicitUsings enabled on every project.

- **AC-002** (ubiquitous): The system shall organize source code into eight projects under `src/`: SharedKernel, Contracts, four Bounded Context modules (ServiceOperations, CatalogInventory, Communication, IdentityAccess), Api (composition root), and Host (Aspire AppHost).

- **AC-003** (ubiquitous): The system shall organize test code into six projects under `tests/`: one test project per Bounded Context, one Architecture.Tests project, and one E2E.Tests project (skeleton).

- **AC-004** (ubiquitous): The system shall pin all NuGet package versions centrally in `Directory.Packages.props` using Central Package Management, with no version specified in individual `.csproj` files.

### Bounded Context isolation

- **AC-005** (ubiquitous): The system shall enforce that no Bounded Context module imports types from any other Bounded Context module. Cross-BC communication shall occur only through integration events published in the Contracts assembly.

- **AC-006** (ubiquitous): The system shall enforce that EF Core types are used only within the `Infrastructure/` and `Integrations/` folders of each Bounded Context. Domain and Features folders shall not reference EF Core.

- **AC-007** (ubiquitous): The system shall enforce that the SharedKernel assembly uses RiseOn.ResultRail (Upshot<T>) for the Result pattern and contains only tactical DDD base classes (Entity, ValueObject, IAggregateRoot, IDomainEvent, IIntegrationEvent, BusinessRuleViolatedException) and does not contain any business-domain types, enums, or validation rules.

- **AC-008** (ubiquitous): The system shall assign each Bounded Context its own PostgreSQL schema (service_operations, catalog_inventory, communication, identity_access), with no cross-BC DbContext.

### Dependency injection

- **AC-009** (ubiquitous): The system shall use RiseOn.AutoInject for automatic registration of handlers, validators, and infrastructure services within each Bounded Context via `[InjectService]` attributes, while maintaining explicit BC-level module registration in the composition root.

### Vertical Slice Architecture

- **AC-010** (ubiquitous): The system shall organize each use case within a Bounded Context as a Vertical Slice folder containing Command (or Query), Handler, Validator, and Endpoint files. No technical folders (Services/, Controllers/, Repositories/) shall exist at the BC root level.

- **AC-011** (ubiquitous): The system shall expose HTTP endpoints exclusively via ASP.NET Core Minimal APIs, mapped through a `MapGroup` per Bounded Context under `/api/v1/<bc-slug>`. No MVC controllers shall be used.

### Data access and persistence

- **AC-012** (ubiquitous): The system shall generate all aggregate root identifiers as UUID v7 (time-ordered) in domain constructors, not auto-generated by the database.

- **AC-013** (ubiquitous): The system shall populate `created_at` and `updated_at` audit columns automatically via an EF Core `SaveChangesInterceptor`, using shadow properties to keep the domain model clean.

- **AC-014** (ubiquitous): The system shall enforce optimistic concurrency using PostgreSQL's `xmin` system column mapped as a `uint` row version shadow property.

- **AC-015** (event): When the API starts in Development environment, the system shall run EF Core migrations automatically for all Bounded Context DbContexts before accepting requests.

### Event-driven architecture (Wolverine)

- **AC-016** (ubiquitous): The system shall configure Wolverine with in-process transport for Phase 1, auto-discovering message handlers from all four Bounded Context assemblies.

- **AC-017** (ubiquitous): The system shall persist all integration events to an outbox table within the same database transaction as the aggregate mutation, using Wolverine's EF Core outbox integration.

- **AC-018** (ubiquitous): The system shall run Wolverine's DurabilityAgent as a background hosted service to relay unprocessed outbox messages to the in-process transport.

### Local development experience

- **AC-019** (event): When a developer runs `dotnet run --project src/Host/CatCar.AppHost.csproj`, the system shall start a PostgreSQL container, the CatCar API, and the Aspire Dashboard, with the API waiting for PostgreSQL health before starting.

- **AC-020** (ubiquitous): The system shall expose health check endpoints at `/health/live` (liveness) and `/health/ready` (readiness, including PostgreSQL connectivity).

- **AC-021** (ubiquitous): The system shall generate an OpenAPI document from code and serve SwaggerUI at `/swagger` in Development environment.

- **AC-022** (unwanted): If a request fails validation or encounters a domain error, then the system shall return a ProblemDetails response (RFC 7807) with `traceId`, `title`, `status`, and `detail` fields.

### Testing infrastructure

- **AC-023** (ubiquitous): The system shall enforce architectural rules via NetArchTest tests that verify: no cross-BC imports (CON-001), no EF Core in Domain or Features (CON-002), SharedKernel purity (CON-003), BC folder structure (CON-004), and Vertical Slice structure (CON-005). These tests shall fail the build if violated.

- **AC-024** (ubiquitous): The system shall provide an `IntegrationTestBase` class that manages a Testcontainers PostgreSQL instance for integration tests, with automatic migration execution.

- **AC-025** (ubiquitous): The system shall collect code coverage via coverlet.collector and publish results in Cobertura XML format, with coverage configuration in `Directory.Build.props` and CI pipeline integration.

### Code quality and formatting

- **AC-026** (ubiquitous): The system shall enforce C# coding conventions via `.editorconfig` at the solution root, with rules for file-scoped namespaces, var preferences, brace style, and StyleCop analyzers.

- **AC-027** (event): When `dotnet format --verify-no-changes` runs, the system shall exit with a non-zero code if any file violates the formatting rules defined in `.editorconfig`.

### Containerization

- **AC-028** (ubiquitous): The system shall provide a multi-stage Dockerfile that builds the API in an SDK container and runs it in an ASP.NET runtime container, as a non-root user, with a health check.

- **AC-029** (ubiquitous): The system shall provide a `docker-compose.yml` that starts PostgreSQL and the CatCar API, with the API waiting for PostgreSQL health before starting.

### CI/CD pipeline

- **AC-030** (event): When a pull request is opened against `main`, the CI pipeline shall execute: restore, build, format check, unit tests, architecture tests, integration tests, coverage report, SAST (package vulnerability scan), and Docker build with Trivy scan.

- **AC-031** (unwanted): If any CI step fails (build, test, format, SAST, Docker scan), then the pipeline shall fail and prevent merge.

### Documentation

- **AC-032** (ubiquitous): The system shall provide a README.md with prerequisites (.NET 10 SDK, Docker), setup instructions (Aspire AppHost or docker-compose), and links to SwaggerUI and Aspire Dashboard.

## Out of scope

- Implementation of domain logic for any Bounded Context (features 02–07).
- Kubernetes manifests, Terraform scripts, or HPA configuration (feature 08).
- JWT authentication or administrative user management (feature 02).
- External customer communication channels (feature 05).
- Production deployment configuration (Phase 2).
